## MODIFIED Requirements

### Requirement: DS-03 条件组合与数量

系统 SHALL 将目录与关键词、类型、匹配模式、扩展名、修改时间取交集；目录/类型 SHALL 在数量限制前生效，目录不额外改变评分。旧请求 SHALL 保持成功结构、合法关键词和评分语义；允许纠正类型过滤过晚造成的少返回，并按 DS-09 统一错误语法为 400。

**B 名称体验授权下的兼容例外（0.3 变更边界）：**

- **变更**：FUZZY + 普通字面查询的名称命中规则与命中排序（双列表合并：名称命中列在仅正文命中之前）属于本 change 有意改变的"评分语义"；Match 字段的解释来源随之明确为名称/正文双分支判定。
- **保留**：目录/类型 FILTER 仍在数量限制前生效；目录过滤不额外改变相对排序规则（两列表叠加同套 FILTER）；CONTENT 评分语义完全不变；EXACT 与高级语法路径的评分语义完全不变；响应结构与错误码（DS-09）不变。

#### Scenario: 条件组合

- **WHEN** 同目录分别使用 NAME、CONTENT、ALL、FOLDER、两种匹配模式及扩展名/时间
- **THEN** 每项同时满足所有条件；ALL 保持文件名称加正文含义，目录用 FOLDER

#### Scenario: 范围与类型不挤占名额

- **WHEN** limit=2，范围外高分项或被排除类型超过原抓取量，仍有两个合格文件
- **THEN** 返回两个合格文件，不因先截断再过滤而少返回

#### Scenario: 目录限定下排序分档不竞争正文

- **WHEN** 目录限定开启，且同目录内同时存在名称命中与高正文评分文档
- **THEN** 名称命中列在仅正文命中之前（双列表结构保证），且 FILTER 先于 limit 生效不变

#### Scenario: CONTENT 评分语义不变

- **WHEN** 使用 CONTENT 范围进行合法关键词查询
- **THEN** 命中集合与评分语义与 A 阶段交付一致，不引入名称子串分支


#### Scenario: ALL字面输入的正文解析边界

- **WHEN** B普通FUZZY名称路径收到+、-、方括号等字面字符
- **THEN** ALL正文分支先字面转义，保持正文分词与词间规则，分析无词项时正文无命中；这是该字面路径的输入解释边界，不改变CONTENT/EXACT/高级语法路径或其评分
