## 契约实现

**GET /api/search**
- 新增可选 `directory`（URL 编码，服务端解码后透传 `SearchRequest.directoryPath`；空白按未设置处理）。
- 空词优先：空 `q` 仍返回 `{"results":[],"count":0}`，不校验来源/服务。
- `serviceSupplier==null` 且非空词 → `503 {"error":<固定文案>,"code":"INDEX_UNAVAILABLE"}`，替换旧 “initializing” 文案（设计允许）。
- 八类 `SearchException.Code` → status：INVALID_DIRECTORY 400、DIRECTORY_NOT_INDEXED 422、SOURCE_CONFIG_UNAVAILABLE 503、INDEX_REBUILD_REQUIRED 409、SCOPE_CHECK_FAILED 503、SEARCH_FAILED 500、INVALID_QUERY 400、INDEX_UNAVAILABLE 503；消息取 `SearchErrorMessages.forCode`，与桌面共享。
- 有/无 directory 的 INVALID_QUERY 一致 400；未知异常统一 500 SEARCH_FAILED；响应与日志均不外泄原始 `getMessage()`/堆栈（堆栈仅 WARN 日志）。
- 每条结果新增 `parentDirectory`（服务器端 `Paths.get(r.path).getParent()`，无磁盘 I/O；无父/不可解析为 `null`）。
- `escapeJson` 重写为逐字符：`\` `"` `\n` `\r` `\t` `\b` `\f` + `<0x20` → `\u00XX`，保证控制字符不产生非法 JSON；非英语文本原样 UTF-8 输出。

**index.html**
- 搜索栏新增 `Server directory` 输入（Enter 提交）与 `Clear`（清范围并保留关键词/过滤重新搜索）。
- 状态栏显示 `N result(s) in X ms — scope: <dir> (includes all subfolders)` 或 `all sources`。
- 结果行新增：目录行 `📂`（范围=该行 `path`）、文件行 `📁↰`（范围=`parentDirectory`，为 `null` 时禁用）、`📋` 复制路径（clipboard API → execCommand 回退 → `window.prompt` 手动复制，不虚报成功）。
- 快捷搜索调用同一 `search()`，保留 q/scope/mode/ext/limit，恰一次提交；token 防迟到响应的机制不变。
- 错误显示 `data.error` 固定文案；DOM 仍走 `esc()`/textContent 路径。
- 未新增 `/api/sources`、`/api/browse` 或任何来源修改 API（`WebAssetsOfflineTest` 静态断言）。

## M-04/M-05 可复现步骤（待 Codex 实机）

前置：桌面启用 Web Server，来源含 `E:\Root`（含子目录与文件）。

1. 浏览器 `GET /api/search?q=<词>&directory=E%3A%5CRoot%5CSub` → 200，结果限于该子树；不带 directory → 全局。
2. `directory` 填来源外路径（如 `C:\Windows`）→ 422 `{code:"DIRECTORY_NOT_INDEXED"}`；填非法路径 → 400 `INVALID_DIRECTORY`。
3. 页面：目录框输入后 Enter/Search；`Clear` 恢复 all sources；目录行 `📂`、文件行 `📁↰` 快捷缩小范围；`📋` 复制路径（含断网/权限拒绝时 prompt 回退）。
4. 重建期间非空词请求 → 503 `INDEX_UNAVAILABLE`；空词仍 200 空结果。
5. 排序、token 迟到响应、复制拒绝行为按既有机制复核。

## 风险与说明

- **422 覆盖探测**：`DIRECTORY_NOT_INDEXED` 与其它状态的差异可推断“路径是否在来源内”，属于用户已知情接受的增量泄露（design D7 记录）；localhost 默认绑定不扩大风险面。
- `parentDirectory` 由服务器按宿主语义计算，前端不做浏览器侧路径切割，Windows/POSIX 混合环境行为正确。
- `WebAssetsOfflineTest` 为静态检查，不代替 M-04/05 交互验收；无浏览器自动化引入。
- 无新增依赖、无 Java 9+ API、无提交/推送。
