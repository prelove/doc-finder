## 改动文件

- `LuceneSearchService.java`：
  - `static void ensureDirectoryScopeSupported(IndexSearcher)`：逐 leaf，`numDocs()==0` 跳过；`Terms!=null && getDocCount()==maxDoc()` 为充分通过；否则全局精确回退 `MatchAll MUST + PrefixQuery(path_scope,"") MUST_NOT`（top-1 定位缺字段 live doc）；空 live reader 直接通过；缺字段→INDEX_REBUILD_REQUIRED，I/O→SCOPE_CHECK_FAILED
  - `checkScopeSupport(searcher)`：以 `getReaderCacheHelper().getKey()` 为键缓存 TRUE/FALSE（仅 SUPPORTED/REBUILD_REQUIRED）；helper==null 不缓存；经 `CacheHelper.addClosedListener`（Lucene 8 实际 API，非 0.4 设想的 `IndexReader.CloseListener`）按 key 逐出；服务 close 清空；listener 注册失败则不缓存
  - 调用点：`scopedDir != null` 时在 acquire 之后、查询之前
- 测试：`DirectoryScopeCompatibilityTest`（7 用例）、test-only `DirectoryScopeCheckBenchmark`（P-00）

## P-00 微基准（100k path_scope 文档，临时 fixture）

| 项 | 实测 |
| --- | --- |
| 索引构建 | ~4.4 s |
| 首次 check（含 Terms 元数据加载） | 518.84 ms |
| 同 reader 重复 check | p50 ≈ 0.00 ms，p95 0.03 ms（快路径 getDocCount 为 O(1) 统计） |
| 精确回退查询（无缺字段） | 208.22 ms（一次） |
| 含删除文档索引（maxDoc=1000/numDocs=999） | 0.05 ms |
| 混合索引 | 正确返回 INDEX_REBUILD_REQUIRED |

结论：快路径成本为统计读取（非逐 term 枚举），回退为一次短查询；reader-key 缓存使同 reader 后续检查接近零成本。**不虚报**为业务搜索加速——本基准仅覆盖能力判定本身。

## 迁移夹具覆盖（目录内断言）

- 纯旧索引 scoped → INDEX_REBUILD_REQUIRED；同一索引 unscoped 正常命中（gate 不触发）
- 混合索引（scope 外 stale doc、不匹配查询词）→ 仍 409（全库门槛，未弱化）
- 已删除旧文档（先提交后删除）→ 不阻断，scoped 正常
- `maxDoc>numDocs` 且全 live doc 有字段 → 快路径不充分时精确回退通过（numDocs 对比不被用作充分条件）
- 全删除 leaf/空 live reader → 通过并返回零命中
- refresh 后新 reader 重新判定（缓存按 key 失效，不复用旧结论）
